# E2E 验证文档

本文档用于记录 E2E（End-to-End，端到端）测试的验证目标、范围、环境、用例执行情况与结论，作为版本发布前的验收依据。

本页内容已更新。

### \\1. 验证范围

- 覆盖用户关键主流程：注册登录、商品浏览、下单支付、订单查询。
- 覆盖主要异常与边界场景：弱网重试、重复提交、非法输入、支付失败回滚。
- 不包含：性能压测、安全渗透、仅接口层验证的用例。

### \\2. 验证环境

- 环境：测试环境（预发数据），与生产同版本部署。
- 浏览器与终端：主流桌面浏览器各一轮；移动端覆盖 iOS Safari 与 Android Chrome。
- 数据：每次执行前重置测试账号与基础数据，保证可重复执行。

### \\3. 用例设计与执行步骤

1. 依据需求与验收标准梳理用例清单，标注优先级（P0 主流程 / P1 异常分支 / P2 体验细节）。
2. 准备测试数据与账号，确认依赖服务（支付、消息、第三方登录）可用。
3. 按主流程 → 异常分支 → 兼容性顺序执行，记录每条用例结果与截图/日志。
4. 失败用例登记缺陷，标注严重级别并指派责任人；修复后回归验证。
5. 汇总执行统计，形成验证结论并归档。

### \\4. 通过标准与缺陷处理

- 通过标准：P0 用例 100% 通过，P1 用例通过率 ≥ 95%，无遗留阻断级（Blocker/Severe）缺陷。
- 缺陷分级：Blocker（主流程不可用）、Severe（功能异常但有绕行方案）、Normal、Minor（体验问题）。
